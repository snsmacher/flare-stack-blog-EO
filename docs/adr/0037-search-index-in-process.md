# Match the Search Index in Process, as Substrings

The PostgreSQL port inherited D1's shape: a `tokens` column filled by `Intl.Segmenter`, matched with `to_tsvector('simple', tokens) @@ websearch_to_tsquery(...)`. That column only existed because FTS5 on D1 tokenizes Chinese badly; on PostgreSQL it is a redundant middle layer, and it cannot work: `tsvector` matches whole lexemes, so 「中行」 could never find 「中国银行」 — the stored lexemes are 中国 and 银行, and one lexeme is not part of another. The app now reads every document into the instance when `search_index_meta.version` moves and matches case-insensitive substrings, ranking by the field the whole query landed in (title, tags, summary, content, scattered words) and then by weighted occurrence counts. Orama was measured first and rejected: its Mandarin tokenizer is the same `Intl.Segmenter`, and it ORs the query's tokens with fuzzy tolerance, so 「借记卡」 returned documents that do not contain the word. The version is a timestamp plus a random suffix, because the version is what invalidates a warm instance and two writes inside one millisecond must still produce two versions. The cost is one copy of every Post's text per instance (twice, with the lower-cased copy); past a few hundred Posts this becomes a `pg_trgm` index instead.
